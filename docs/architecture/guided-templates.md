# Guided templates

Moved verbatim from `CLAUDE.md`. Paths in links are relative to this folder.

### Guided templates

A workout can be **guided**: instead of assignments it carries `WorkoutTemplate.steps`, a list of `GuidedStep` (`name`, `seconds`, optional `bothSides`, `hint`, `transitionSeconds`, `spokenName`) that the app will play through by time alone — no reps, sets or load. Guided is independent of `category`. Steps are plain values on the template, like `scheduledWeekdays`, so there is no table; only the library import writes them, and it replaces the list whole. A guided template has **no assignments** (the import refuses both). `isGuidedTemplate` ([guided-steps.ts](../../src/domain/guided-steps.ts)) is the one test for it.

**`resolveGuidedSections(steps)` is the one place steps become a timeline** — the later start screen, progress bar, announcements and run all read its flat `GuidedSection[]` and never recompute from the steps. Each section is `{ kind: 'transition' | 'exercise' | 'sideSwitch', stepIndex, side?, seconds, startSeconds }`: a 5 s transition before the first step (fixed, whatever that step's own `transitionSeconds` says), then each further step's `transitionSeconds` (default 5) before it, and a `bothSides` step becomes left, a 3 s side switch, right, **each side half of `seconds`** (`guidedSideSeconds`, rounded down, at least 1 s): `seconds` is always the whole step, as the import writes it; the start screen shows `2 × 1:15` for 150, the announcement names one side's time. A transition and a side switch carry the `side` of the exercise they lead into and belong to that step. Nothing follows the last step: the end is an event, not a section. `describeGuidedFacts` / `describeGuidedStepDuration` are the start screen's strings; `loadTemplateMinutes` / `loadTemplateExerciseCounts` take their numbers for a guided template from the sections and the steps. `startSessionFromTemplate` refuses a guided template — it would materialize an empty strength session — so the UIs go to `/guided/:templateId` through `navigateToGuidedStart` ([session-navigation.ts](../../src/lib/session-navigation.ts); it hands the plan entry over as router state and `readGuidedStartState` reads it back).

**The guided stage is fixed landscape, light for the start screen and dark for the run.** [GuidedStage.tsx](../../src/components/GuidedStage.tsx) is the full-screen frame every screen of a guided session stands on, with `tone="light"` (default: paper ground, `theme-color` untouched — the start screen) or `tone="dark"` (ink ground, `applyThemeColor(INK_THEME_COLOR)` like the rest mode, restored on unmount — the screens of the running session, from the run ticket on). Dark is the **second dark exception** to the single-theme rule, next to the rest mode, and for the same reason (screen on for minutes, OLED); only what runs is dark, never the start screen. The stage is the **inverse of the portrait lock**: `.guided-stage` in [index.css](../../src/index.css) fills the page in landscape and rotates 90° with swapped `100dvh`/`100dvw` in portrait on a coarse-pointer phone. It is a **portal into `body`, not a child of `#root`** — in landscape the lock rotates `#root` back to portrait, and anything inside would stand upright again (`RestMode` and `Sheet` are portals for the same reason). Its content reads only `--stage-inset-*`, the safe-area insets as seen from the stage (left edge = device top when rotated); the hint dialog ([GuidedHintDialog.tsx](../../src/components/GuidedHintDialog.tsx), an ink card over a scrim in both tones) lies *inside* the stage for the same reason and is not a `Sheet`. The rotation direction is a fixed assumption (clockwise): iOS's orientation lock cannot be detected, and `data-screen-angle` only exists in landscape. At most one lime surface per screen: none on the start screen, since nothing is up next yet, and its start button is ink. [GuidedStartPage.tsx](../../src/pages/GuidedStartPage.tsx) is the start screen (steps left on `surface-sunken`, facts as one sideways-scrolling row of pills right); the button starts the run (`startGuidedSession`, then `navigate(…, { replace: true })` to `/guided/run/:sessionId`); with another session already active it is replaced by the shared `ActiveSessionHint` and a "Zur laufenden Einheit" button. On `TemplateDetailPage` a guided workout shows its steps read-only (`GuidedStepsCard`) with a link to the start screen, and no exercise or assignment editing: a guided template has no assignments. Test anchors: `data-guided-stage` (the screen: `start`, `loading`, `missing`) with `data-guided-tone`, `data-guided-template`, `data-guided-steps`, `data-guided-step`, `data-guided-facts`, `data-guided-hint`; [guided-start.spec.ts](../../e2e/guided-start.spec.ts) reads them.


### The run (ticket 03: signal only)

**A guided run is a normal `WorkoutSession` without `WorkoutSessionExercise` rows.** `startGuidedSession` ([guided-session-actions.ts](../../src/db/guided-session-actions.ts)) writes it with `guided: { steps, events }` — a *copy* of the template's steps (later imports don't rewrite history) and the event list, which starts with `{ type: 'start', at }`. It shares the "only one active session" check (in the same transaction as the insert; an already active session of either kind comes back as its id), the week context (`resolveSessionWeekContext`) and the plan-entry link (`findPlanEntryForStart`) with `startSessionFromTemplate`, which stays untouched for strength. `isGuidedSession` is the test for it; `/session/:id` of an active guided session redirects to `/guided/run/:id`, so the bar, the Now sheet and the plan all find their way back without knowing the kind.

**`deriveGuidedRunState(steps, events, now)` is the whole run** ([guided-run.ts](../../src/domain/guided-run.ts)): phase (`transition` — a transition and a side switch both —, `exercise`, `finished`), current section, next exercise, remaining seconds (rounded up), progress overall and per step, and the due signal. No clock: `now` is a parameter, so a reload or a return from the background just recomputes the right time. Events are a union (`GuidedEvent`, schema in `export.ts` as `guidedEventSchema`); tickets 04/05 add types and fold them in `playedMs`. `addGuidedEvent` is the pure appender that rejects nonsense. **One signal at the end of every exercise section** (each side of a two-sided step, and the last exercise = the end), key `exercise-end:<sectionIndex>`; it is due only within `GUIDED_SIGNAL_MAX_DELAY_MS` (2 s, the freshness rule of the set-timer cues), so a return after minutes catches nothing up. The caller remembers played keys.

**The end is automatic and exact.** `GuidedRunPage` ticks every 250 ms and calls `completeGuidedSession` once the state is `finished`; the action sets `completed` with `completedAt = start + total duration` (not `now`: a late return keeps the real length and the right week) and does nothing before that moment, after an abort or for a strength session. The plan entry is *taken* from the start (any non-aborted session with its `planEntryId`) and *done* once completed — nothing is written to the entry. The finish screen (forest card, "Erledigt", duration and steps) is also what you see after a reload of a completed session. Abort ("Einheit beenden") lives on the pause screen.

**Sound** is `playGuidedSignal()` in [sound.ts](../../src/lib/sound.ts): one short tone through the same unlock/wake logic and `RESUME_GRACE_MS` as the timer chime, after `setAmbientAudioSession()`; `speechSynthesis` is never used. The start button calls `primeTimerSound()` and `setAmbientAudioSession()` synchronously in the tap, before any `await`. The X only minimises (`navigate(-1)`); while the screen is closed nothing sounds. The run page holds its own `keepScreenAwake()` while the session is active, whatever `keepScreenAwakeEnabled` says.

**Weekly volume:** `buildWeeklyVolume` counts a completed guided session as a unit (the completion itself replaces "at least one ticked work set"); an aborted one does not. Yoga/Faszien land in `WeekVolume.mobility`, a guided session of category strength in `strength` with zero volume.

Screens, lime and colour: the run stands on `GuidedStage tone="dark"`; in the exercise the name is lime text (the one lime), in a transition the ring is (the name is white), the progress bar is white/dimmed paper, the finish screen has no lime. The side is a large `GuidedSideTag` (L/R) at the heading; the `i` opens `GuidedHintDialog` for the current step (in a transition: the step that follows) with "Die Zeit läuft weiter" and closes itself at the next section. Anchors are listed in `CLAUDE.md`.

**Controls (`skip`, `extend`, `back`, `startNow`)** are further `GuidedEvent` types, folded in `foldTimeline` (and in the backup schema). The play position is *section + offset*, not a second on the base timeline, because `+15 s` lengthens the running exercise (one side of a two-sided step) by `GUIDED_EXTEND_SECONDS` and pushes everything after it; the state is derived from the *effective* sections (`Timeline.sections`). `skip` jumps to the first section of the next step (from a transition: skips the step it leads into; from the last step: ends the run), `back` to the first section of the previous step (first step: from the top; every `extend` from there on is dropped, so a replay runs at its own length), `startNow` ends a transition or side switch. `addGuidedEvent(events, event, steps)` needs the steps and refuses `extend` outside an exercise, `startNow` inside one, and all four before the start, while paused and after the end. A skipped exercise never "ends": its end signal stays off (`Timeline.skipped`); a `back` or `restart` bumps `rewinds`, which is part of the signal key (`exercise-end:3:1`) so a replayed exercise sounds again. `GuidedRunState.skippedStepIndexes` lets the finish card count real steps. The hint dialog closes on any section change, including a jump.


### The step log (ticket 06)

**`deriveGuidedProtocol(steps, events, until)`** ([guided-run.ts](../../src/domain/guided-run.ts)) is the pure derivation: one `GuidedProtocolEntry` per exercise section (per side for a two-sided step; transitions and side switches never appear) with `status` `done` / `skipped` / `extended` / `aborted`, `plannedSeconds` (template, without `+15 s`) and `actualSeconds` (played time of the **last pass**, no pauses; `restart` and `back` reset it, a `skip` keeps what ran before it, skipping a left side also marks the right side). Sections not reached are left out; the exercise a run was aborted in is `aborted`. It is written once — `completeGuidedSession` (until = computed end) and `abortGuidedSession(id, now)` (until = now; also stamps `completedAt = now`) store it as `GuidedRun.protocol`, in the backup schema as an `.optional()`. The history detail page shows it instead of sets (`HistorySessionPage`); the analysis export writes it to `protokoll.csv` (see `import-export.md`).


### Restrictions on guided steps

A restriction targets a step by name (`{ step }`, every guided template with that step, or `{ template, step }`) — see `restrictions.md`. **`startGuidedSession`** resolves them for the start day with `resolveGuidedSteps` and freezes the result: `GuidedRun.steps` holds **only the played steps**, with adjusted seconds, so `guided-run.ts` (the fold over steps and events) never learns about restrictions; `pausedSteps` (template index, step, names, until) and `adjustedSteps` (index in `steps`, names, `secondsBefore` only when the seconds changed, notes) are for display and the log only, both left out when empty. All steps paused → it throws „Heute sind alle Schritte pausiert.“; there is no „trotzdem“ for steps.

**Log.** `completeGuidedSession` and `abortGuidedSession` pass `deriveGuidedProtocol` through `withRestrictionProtocol` ([restriction.ts](../../src/domain/restriction.ts)): `stepIndex` is mapped back to the **template** position (so `schritt_nr` stays stable in the export), every paused step gets a `paused` entry (per side for a two-sided step, `actualSeconds` 0) at its place — after an abort too, the pause was fixed at start — and paused and adjusted entries carry `restrictedBy`. `plannedSeconds` of an adjusted entry is the adjusted value.

**Announcements.** They say the duration, so an adjustment changes the sentence. `loadGuidedTexts(templateIds, now)` adds the sentences of the steps effective on that day to the template's own; „Ansagen erzeugen“ on the start screen therefore generates them too, and `startGuidedSession` checks availability against the effective steps. Without them the run falls back to „Nur Ton“ as before.

**Start screen.** Paused steps stay at their place, greyed (`text-content-secondary`), with „Pausiert bis 14.12. · Beispiel A“ and no duration; an adjusted step shows its new duration, „30 s statt 45 · Beispiel A“ (or „Hinweis · …“ for a note only) and each note as its own line (`describeGuidedStepRestrictions`). The facts count only played steps. All paused → a sentence instead of „Einheit starten“. Anchors: `data-guided-step-restriction`, `data-guided-all-paused`.

**Stage.** It knows nothing of paused steps. The note of an adjusted step is a text line under the name while the exercise runs (`data-guided-note`) and is **not** announced — announcements are pre-generated MP3s, a note from an import has none.

### Generating the announcements (ticket 08)

**Text and set**: [guided-announcements.ts](../../src/domain/guided-announcements.ts) builds "Als Nächstes: {spokenName ?? name}, {links/rechts}, {Dauer}" (side omitted for one-sided steps, up to 90 s in seconds, above in minutes) and "Geschafft."; `requiredAnnouncementTexts(steps)` is the de-duplicated set, one sentence per exercise section plus "Geschafft.". **Generation** ([announcement-actions.ts](../../src/db/announcement-actions.ts)): `generateAnnouncements(templateIds, options)` skips sentences already stored for the current voice, checks key and `navigator.onLine` (no request without them), checks the quota with the characters of the **missing** sentences and asks via `confirmOverage` (no callback means no), then synthesizes one by one and stops at the first error, keeping what was stored. It never throws; the result carries a displayable message. `getAnnouncementAvailability(templateId)` drives the start screen: "Stimme + Ton" is disabled, "Keine Ansagen für diese Vorlage" and "Ansagen erzeugen" show while anything is missing. The library import starts the generation **after** its transaction (`LibraryImportSection`), and its message comes in addition to the import summary. Playing the announcements and persisting the chosen mode belong to the run (ticket 09); the choice on the start screen is local state until then.

**Stimme + Ton (ticket 09).** `GuidedRun.audioMode` (`'voice' | 'tone'`, missing = tone) is the session's choice; `AppSettings.guidedAudioMode` is the last choice (additive, in the backup schema) and preselects the start screen. `startGuidedSession(…, { audioMode })` downgrades `voice` to `tone` when a sentence is missing and then leaves the remembered choice alone; `setGuidedSessionAudioMode` (the run's pill) writes session and settings together, appends **no event** (time is untouched) and refuses `voice` without all announcements. `recordGuidedControl` spreads `session.guided` — never rebuild that object from `steps`/`events` only, it would drop `audioMode`/`protocol`. `deriveGuidedRunState().dueAnnouncement` (`{ key, text, dueAt }`, keys `announce:start[:n]`, `announce:jump:<n>` and `announce:exercise-end:<i>[:n]`) uses the signal's freshness rule; a skipped exercise says nothing at its end, but the jump itself (`skip`, `back`; `Timeline.lastJump`) announces the exercise it lands in — or „Geschafft.“ when a skip ends the run; text comes from `buildNextAnnouncement` / `GUIDED_DONE_TEXT`. The run screen reads the MP3s once from IndexedDB (`loadAnnouncementAudio`, copies), decodes them in timeline order and hands each over as soon as it is ready (`decodeAnnouncements(audio, onDecoded)`, shared AudioContext unlocked at „Einheit starten“): a due announcement whose buffer is still decoding waits while it is fresh instead of being consumed silently — otherwise `announce:start`, due the moment the screen mounts, never sounded. It plays via Web Audio `ambient`, 0.7 s after the signal at an exercise end, immediately at the start and after a jump; no network, no `speechSynthesis`. Test anchors on the stage: `data-guided-audio`, `data-guided-announced` (last announcement key handed to the player, set even if decoding failed), `data-guided-audio-pill` ([guided-voice.spec.ts](../../e2e/guided-voice.spec.ts)).

### Spoken guidance

A step may carry **`guidance`**: two to four sentences written for listening, delivered by the library import like `hint` (trimmed, empty dropped, at most 600 characters counted like the TTS quota, compared by `sameGuidedSteps`; format in `docs/claude-projekt/import-format.md` §6.1). It is a value on `WorkoutTemplate.steps` — no index, no new DB version — and in the backup schema. `hint` stays the short reading text; the „i“ shows both (`GuidedHintDialog`, `hint?` + `guidance?`; without a hint only the guidance, anchor `data-guided-guidance-text`), and the guidance is always readable there, switch on or off.

**One sentence, one MP3.** With guidance, `buildNextAnnouncement` appends it to the same sentence: „Als Nächstes: Beispiel A, 40 Sekunden. {guidance}“ — only when the step carries `guidanceSeconds` and never before the right side of a two-sided step (that one keeps the plain sentence and the 3 s side switch). `requiredGuidanceTexts(steps)` builds the template variant through the same function with a placeholder, so generation, measurement and run mean the same sentence.

**Measured, not estimated.** `generateAnnouncements` generates the plain **and** the guidance sentences (template steps and the steps effective that day), measures every new MP3 with `measureAudioDuration` (own `OfflineAudioContext`, decodes a copy, `null` on failure) and stores `Announcement.durationMs`. A guidance sentence without a duration counts as missing (`findMissingTexts`) and is regenerated on the next run; `saveAnnouncement` replaces a record without a duration when a measured one arrives. Plain sentences never need a duration. `AnnouncementAvailability.total/missing/complete` count only plain sentences — a missing guidance never blocks „Stimme + Ton“; `guidance: { available, complete, totalSeconds? }` is separate and computed on the effective steps.

**Fixed at start.** `startGuidedSession(…, { guidance })` (default `AppSettings.guidedGuidance`, additive, in the backup) runs with guidance only when the resolved audio mode is `voice` and `applyGuidance(steps, durations)` succeeds; then every snapshot step with guidance carries **`guidanceSeconds`** = `max(planned transition, ⌈0.7 + duration + 2⌉)` (`GUIDED_ANNOUNCEMENT_DELAY_SECONDS`, `GUIDED_GUIDANCE_PAD_SECONDS`). Otherwise no field is written and the remembered choice stays (same rule as the audio mode). `guidanceSeconds` exists only in `GuidedRun.steps`; the import drops it. `resolveGuidedSections` takes it as the transition length — **also for the first step**, which is otherwise a fixed 5 s — so `guided-run.ts`, jumps, `startNow`, the log and `completedAt` follow without knowing about guidance. Sessions without the field resolve exactly as before. Switching to „Nur Ton“ mid-run keeps the long transitions; „Sofort starten“ cuts them short.

**One announcement at a time.** `sound.ts` keeps at most one running announcement: `playAudioBufferWhenAwake` stops the previous one, `stopAnnouncement()` (re-exported from `announcement-audio.ts`) stops it and discards one still waiting for the context to wake. The run screen calls it on every change of section, phase or audio mode (declared before the announcement effect, so a section change stops first and then plays) and on unmount. After a pause the guidance is **not** repeated.

**Start screen.** Below the audio choice, „Mit Anleitung“ / „erklärt jede Übung vorher“ (`role="switch"`, anchor `data-guided-guidance`, ink not lime, ≥ 44 px) — shown only with „Stimme + Ton“ selected and `guidance.available`, disabled until `guidance.complete`; the generation hint then reads „Anleitung noch nicht erzeugt“. Switched on, the duration pill reads „≈ {n} min mit Anleitung“ from `guidance.totalSeconds`. The choice is passed (and remembered) only when the switch was selectable. Test: [guided-guidance.spec.ts](../../e2e/guided-guidance.spec.ts), which answers Google with a silent WAV (`silentWavBase64`) so WebKit can decode and measure it.
